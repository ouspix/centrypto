# Backtest archive recovery

The default `prisma/backtest.db` points to the recovered archive on the SSD-backed CentryptoDB filesystem, shared with Ubuntu at `/mnt/wsl/centrypto-backtests`. The original damaged file is preserved as `prisma/backtest.corrupt-20261106.db`. The `Centrypto local PostgreSQL` Windows startup task keeps that distro running; its keepalive script recreates the shared bind mount.

The November 6 recovery copied 1,254,594 ticks, 6,301,960 candles, 7,316,148 features, 7,318,367 execution books and 21,429 ingestion records. SQLite's full integrity check returned `ok`. Price/spread and candle sanity checks found no invalid rows. Recovery omitted 71 damaged feature row ranges covering at most 2,219 row IDs. This is a usable archive with explicit gaps, not a lossless restoration. See [the coverage and gap audit](../reports/backtest-recovery-2026-11-06.json).

`scripts/recover_backtest_archive.py SOURCE NEW_DESTINATION` copies bounded row-ID ranges without writing to the original. It refuses non-empty WAL files, checkpoints progress, bisects damaged ranges, rebuilds indexes and runs a full integrity check. Use a separate destination directory with enough physical disk space. Interrupted recovery can resume only against the same source fingerprint; a source changed during recovery invalidates the result. Never activate a partial or unchecked destination. Preserve the adjacent `.recovery.json` report: the desk's catalogue and simulation tools use it to disclose omitted rows and refuse incomplete recovery results.

`scripts/prepare_backtest_storage.sh` sets up the shared storage when run as root inside CentryptoDB. It is idempotent and preserves the previous keepalive script before adding mount setup. This storage is for historical research and is separate from the live market collector database.

Agents must call `backtest_catalog` and choose a listed symbol, historical window and feature interval. The recovered archive contains 10-second features; the adapter supports 10, 30 and 60 seconds. Runs remain limited to six historical hours, three native perpetuals and two simulations per shift, with a 90-second subprocess deadline. Results expose requested-window coverage, archive recovery status, fees/slippage assumptions and synthetic-candle limitations. Simulation success does not validate a live thesis.

The desk result includes `endingPortfolio`: marked equity, realized P&L after fees, unrealized P&L, all fees paid and remaining simulated positions. Trade count, win rate and turnover describe closed trades only. A run with zero closed trades can still have paid entry fees and an open position. `executionAssumptions` records preset fees/slippage, stop-before-target ordering, execution-book fallback and the absence of funding payments or forced end-of-window liquidation. `symbols_with_insufficient_history_rows` flags row-level exclusions; it does not mean an entire symbol was excluded for the whole run.
